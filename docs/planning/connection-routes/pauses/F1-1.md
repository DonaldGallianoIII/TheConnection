# F1-1: two files outside F1's work set that the exit record makes wrong

Model:  Claude Opus 5.5 (the F1 lane agent), 2026-10-16
Status: unreviewed
Pause:  settled by a2 for the owner, 2026-10-17, option 1

## The question

F1's brief names the files F1 may edit. The wait exit record makes two
files outside that list say something false. May F1 change them, or
does the architect change them at the merge?

### 1. `tests/test_shared.py`, line 935

`SharedTest.test_folders_made_after_init_get_the_group_and_setgid` runs
`tc wait b --timeout 0` and then asserts the exact list of every file
under the four shared folders. Since F1, that wait leaves its exit
record, `mail/to-b/.wait.exit`, beside its lock, as C5 says it must. The
list lacks it, so both subtests (primary and supplementary group) fail:

```
FAIL: test_folders_made_after_init_get_the_group_and_setgid (group='primary')
First differing element 7:
'mail/to-b/.wait.exit'
'mail/to-b/.wait.lock'
```

The mode check on the next line passes: the record is 0640, which
`shared_as` already wants for any file in an inbox that is not a lock.
The fix is one entry, `"mail/to-b/.wait.exit",` before
`"mail/to-b/.wait.lock",` in that list, and one clause in the test's
docstring ("the wait lock and its exit record from a wait that times out
at once").

Until it is settled, the full Python suite has these two known
failures, and every F1 commit message says so.

### 2. The legend's words, in `board/look.js` (not `board/live.html`)

The brief lets F1 change `board/live.html`'s legend words "if they say
the board cannot tell how a listener went". `live.html` holds no legend
words: it prints `LEGEND_WORDS` from `board/look.js`, lines 718 to 721:

```
the board cannot see a crash after reading (it looks working for up to
10 min) or, with no board page open, when a listener went (mail that
came meanwhile counts as a wake)
```

With F1's tc, the second half is no longer true for a listener that was
killed: its record says `listening`, so the board reads it `down` even
when mail came meanwhile, and after a restart too. It stays true for a
listener whose tc wrote no record (a tc from before F1). C5 has the
words: "with no board page open, the board cannot tell when a listener
went, unless its exit record says why, so without one it gives mail the
benefit of the doubt".

`tests/board-patch.test.mjs`, line 144, asserts the legend contains
`with no board page open, when a listener went`, so a change to the
words needs that line changed in the same commit.

`qa/human/board-live.md` step 16, the bullet that starts "The legend says
what the states cannot see", repeats the legend's words. That file is in
F1's work set; F1 leaves that bullet as it is, because it describes the
page as `look.js` draws it today.

## The options

1. **Extend F1's work set** to `tests/test_shared.py` (the one entry and
   the docstring clause), `board/look.js` (the legend's second case, to
   C5's words, for example `or, with no board page open, when a
   listener went, unless its tc wrote an exit record (without one, mail
   that came meanwhile counts as a wake)`), `tests/board-patch.test.mjs`
   line 144 to match, and the `board-live.md` bullet.
2. **The architect makes the same changes at the merge**, and F1's
   handoff lists them.
3. **Leave the legend** as it is (true for a tc from before F1, which a
   machine may still run until every session re-arms) and change only
   `test_shared.py`.

## Recommendation

Option 1. Each change is a line or two, each is forced by the record C5
specifies, and leaving `test_shared.py` red hides any other failure in
that suite. If the architect prefers option 2, F1's handoff names the
exact lines.

## Ruling

Settled by a2 for the owner, 2026-10-17: option 1. F1's work set takes
`tests/test_shared.py` (the one `"mail/to-b/.wait.exit",` entry and the
docstring clause), `board/look.js` (the legend's second case, in C5's
words) and `tests/board-patch.test.mjs` line 144, in the same commit as
`look.js`. Both behavior changes are confirmed: a killed listener stays
`down` past the 10-minute window and after a restart, and the board's
date check takes 2 s of slack (`WAIT_EXIT_TIME_STEP_SECONDS`).

Built by the F1 finish (Claude Opus 5.5, unreviewed): the entry and the
clause in `test_shared.py`; `WAKE_WORDS` in `look.js` now reads "or,
with no board page open, when a listener went, unless its exit record
says why (without one, mail that came meanwhile counts as a wake)";
`board-patch.test.mjs` asserts that whole clause; and the legend bullet
of `qa/human/board-live.md` step 16 says the same.
