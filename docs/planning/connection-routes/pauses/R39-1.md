# R39-1: tc has no EXIT_ constant for code 0

Model:  Claude Opus 5.5 (the R39 lane agent), 2026-10-17
Status: unreviewed
Pause:  open. The test carries on with the exception named below.

## The question

The R39 brief, item 2, asks that each code in the README's exit table be
"a value tc defines as an EXIT_ constant". Codes 1 to 11 are:
`EXIT_REFUSED` 1, `EXIT_TIMEOUT` 2, `EXIT_ALREADY_LISTENING` 3,
`EXIT_QUEUED` 4, `EXIT_ALERT` 5, `EXIT_BAD_NAME` 6, `EXIT_GATE_REFUSED`
7, `EXIT_TOO_LARGE` 8, `EXIT_USAGE` 9, `EXIT_BUSY` 10,
`EXIT_FAR_UNKNOWN` 11. Code 0 is not. tc never exits 0 by name: a good
run ends when `main()` (`tc:9651`) returns and Python exits 0 on its own.
The brief also says no change to tc in this lane.

## Options

1. **Keep 0 as the test's one exception.** `tests/test_readme.py` names
   it `SUCCESS_CODE` and checks codes 1 to 11 only. Nothing else changes.
2. **Add `EXIT_OK = 0` to tc** in a later lane, as a named constant
   nothing has to call (or `sys.exit(EXIT_OK)` after `main()`), and drop
   the exception from the test.

## Recommendation

Option 1. Exit 0 is the process's own success, and tc never writes the
number. A constant for it would name what every Unix tool already means
by 0, and the contract's table already fixes the meaning. Option 2 is a
one-line change for a fixer if the owner wants every row backed by a
name, and the test then loses its exception.
