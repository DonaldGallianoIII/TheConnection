  The `listeners()` half is proved on a private mailbox by the new test
  below; on a shared one it rests on the code holding no such read.

**Added, item 2:**
`WakeLockPlaceTest.test_on_a_private_mailbox_the_old_place_is_never_read`
(`tests/test_wake_files.py:686`). Private mailbox, name `x`. Two
children hold `mail/.wait-x.lock` and `mail/.watch-x.lock`. Then, per
kind, each in its own subtest: the old lock was held throughout (else
the case proves nothing, `:728`); `listeners()` in process gives no pid
for `x` (`:731`); `tc health --json` gives none under `listeners` or
`watchers` (`:733`); a new background `tc wait x` and then `tc watch x`
each hold their own lock in `mail/to-x/`, proven in `/proc/locks`
(`:736`); health then names each one's pid (`:739`). The wait and
watch start one after the other, so they never race to make the inbox.
Every child is killed by its own pid with the root.

**Added, item 3:**
`FarKeyReadsTest.test_a_shared_group_named_like_the_running_login_reaches_the_far_key_as_another_member`
(`tests/test_gate.py:1935`). `share()` makes a shared mailbox and joins
`b`; `.shared` is then rewritten by hand to the running login, and
`grp.getgrnam` is patched to answer that name with the running user's
own group, so one user stands in on any machine. In process, under the
patch, each in its own subtest: tc's own `health_snapshot` gives the
login as `shared_group` (the guard, `:1976`); the gate's health exits 0

user database entry, or is spelled like the joined name `b`
(`SHARE_JOINED_NAME`, which `share()` now uses), since far_words keeps
a mailbox name whole.
