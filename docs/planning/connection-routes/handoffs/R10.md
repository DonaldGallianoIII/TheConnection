        user's ssh card"), word for word

Under a shared mailbox one member could write an ssh card for a name
nobody claimed, and every other member's send to that name then ran the
sender's own ssh, with the sender's keys, to the writer's target and
remote program. Now the ssh route, in `tc send` and in `tc flush`,
follows a card only when the file tc opened for it is a regular file
with one name, owned by the sender or by the init user, whose `name`
field is its file's name. Anything else refuses before ssh runs.

## Item 1: one check, in one place

1. `tc:6732` `ssh_card_distrust(name, card, st, trusted)`: the one
   check. It returns every reason that holds, so a card failing two
   ways names both: a second name (`tc:6753`, `st_nlink != 1`), an
   owner not in `trusted` (`tc:6755`), and a `name` field that is not
   `name` (`tc:6757`). `card` and `st` come from one open, so what is
   judged is the file whose bytes were read.
2. `tc:6329` `read_regular_file_seen`: the old body of
   `read_regular_file`, one open (`O_RDONLY | O_NONBLOCK | O_NOFOLLOW`,
   `tc:6345`), one `fstat` on that descriptor, the read, and it hands
   back `(text, st)`. A symlink raises `LinkRefused` (`tc:6293`), a
   `ValueError` subclass, so every caller that caught `ValueError` still
   does. `read_regular_file` (`tc:6299`) now returns its text, every
   refusal as before.
3. `tc:6656` `read_card_seen`: `(card, st)` from that one open, the same
   refusals and words as `read_card`; `read_card` (`tc:6636`) returns
   its card, so the gate's `deliver_once` and every other caller work
   as before.
4. `tc:6698` `shared_owner`: the init user's id, by `fstat` on its own
   `O_NOFOLLOW | O_NONBLOCK` open of `ROOT/.shared`. `tc:6717`
   `trust_frame(share)`: `None` on a private mailbox, else
   `followed = (this user, init user)` (`tc:6729`) for send and flush,
   and `init_only` for the marks.
5. Words are constants, `tc:1354` to `tc:1400`: `DISTRUST_WHY` and
   `DISTRUST_MARK` per kind, the joins, `DISTRUST_FIX_WORDS`,
   `DISTRUST_SEND_WORDS`, `DISTRUST_FLUSH_WORDS`, and the two fallbacks
   for a name tc cannot say.
6. `tc:6762` `link_distrust`: a link's writer, for the words only, by
   `fstat` on an `O_PATH | O_NOFOLLOW` open of the link itself (never
   what it points at). The refusal was already made by the no-follow
   open that met the link.

## Item 2: send refuses

`tc:6823` `card_route(to, forward=True)`. With `forward` and a shared
mailbox: a card whose route is ssh and that fails the check refuses at
`tc:6878`, exit 1, one line, before anything is written or ssh runs; a
symlink at the card's name refuses at `tc:6863` with the link's words,
whatever it points at. `route_and_deliver` passes `forward` at both of
its card reads (`tc:3949`, `tc:3954`), so the gate (`forward` False)
still answers an ssh card with exit 7 and never prints D43's words to a
far key. The line, for another member's card:

```
tc send: <ROOT>/cards/far-y.json is an ssh card ben wrote, and only ben and the user who ran init (ann) send over it. Nothing sent and no ssh run. The user who ran init (ann) can write it for everyone: tc card far-y --ssh <target>. Or write your own card under a name of your own: tc card <your-name> --ssh <target>.
```

The other kinds' clauses: `is a symlink <writer> made, and tc follows
no card through a link, even one to a card of the user who ran init
(<init>)`; `is a card <writer> owns with a second name (a hard link),
and tc follows only a card with one name`; `names <said>, not <name>
(written by <writer>), and tc follows a card only for the name it
names`. Several join with `; it `. A private mailbox: no check, and a
linked card keeps its old words.

## Item 3: flush

`tc:8126` `queue_route`: the same check, `tc:8171`. A failing card, or a
link, gives no target and `DISTRUST_FLUSH_WORDS`, with the new
`SshWhere.distrust` set (`tc:7847`, default False, so every older
`SshWhere(...)` is unchanged). `cmd_flush` prints those words as they
are on the file's `left` line (`tc:9235`): the file stays where it
waits, never sent, never moved to `refused/`, exit 4, and a later flush
sends it once the card is fixed. `queue_ahead` reads cards through
`queue_route`, so a send's queue check never counts mail to a card D43
will not follow.

## Item 4: health and cards mark it

`tc:6369` `all_cards` now gives `(file name, card, mark)`. The mark,
under a shared mailbox only: for a symlink in `cards/`, and for an ssh
card that fails the check with only the init user trusted. That rule
differs from send's on purpose: a mark is read by every member, so any
ssh card not the init user's is marked, the reader's own too, since
other members' sends will not follow it. `cmd_cards` (`tc:6603`) and
`cmd_health` (`tc:10591`) print `<line>; <mark>`, for example

`test_the_gates_health_never_shows_a_mark_or_a_card` checks the gate's
