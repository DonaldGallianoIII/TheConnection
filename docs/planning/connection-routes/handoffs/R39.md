## The mapping rule

Copied from the test's module block. Everything not named is literal: a
changed word, digit or space fails.

1. A line that is exactly `...` matches one or more whole lines.
2. `...` inside a line matches one or more characters of that line.
3. `/home/you/TheConnection` matches the folder tc is in.
4. `<you>` matches this Linux login, as tc names an outbox branch.
5. `<t>` matches a board token: 32 characters of letters, digits, `-`
   and `_` (serve.py's `secrets.token_urlsafe(24)`).
6. `<name> (pid N)` matches the pid of the listener the chain started
   for that name, exactly. A name with no listener fails.
7. `Ns ago` matches any whole number of seconds.
8. The machine line's `load X / Y cores · mem free Z%` matches any
   numbers in those three places, and `N Claude Code · M Codex` any two
   counts: they belong to the machine, not to tc.
9. `127.0.0.1:8780/` matches any port, because the board runs with
   `--port 0`. The test then asks that port for live.html and needs 200.

Rules 6 to 9 are mine, beyond the brief's `...` and `/home/you/...`.
The README shows pids, ages and machine numbers as one real run's
values, which reads better for a stranger than `...` would. Each rule
covers only digits in one fixed context, and rule 6 is stricter than
`...`: it needs the right pid. A reviewer who wants the README to
say `...` in those places instead can change both together.

How a command runs: `tc`, `~/TheConnection/tc` and `tconn` run a copy
of this checkout's tc placed in the throwaway root, with TC_ROOT unset,
as the reader runs it. The mailbox is then the folder tc is in, which is
the throwaway root (`Story.env` asserts that before every run). What a
command printed is its stdout lines, then its stderr lines. Its exit
must be 0 unless the README says otherwise (the outbox block's "Both
exit 4"). `tc health` finds a fake `nvidia-smi` that prints the
README's `39, 3`, so the GPU words are strict on any machine.
