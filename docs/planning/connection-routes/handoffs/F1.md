## What was built

Line numbers are at `12b523b`.

**Item 1, the writer.** `tc wait <name>` writes `listening <time>` once
it holds its lock (`tc:4911`), then `mail <time>` (`tc:4919`) or
`timeout <time>` (`tc:4923`) while the lock is still held, just before
exit 0 or 2. `write_wait_exit` (`tc:4770`) makes `.wait.exit.tmp` with
`write_new_file` (`O_CREAT | O_EXCL | O_NOFOLLOW`, `WAIT_EXIT_MODE`
0640) by name in the inbox's open descriptor and renames it over
`.wait.exit`, so a link at the record's name is replaced, never
followed. The descriptor is the same folder the lock was taken in:
`hold_wake_lock(..., keep_inbox=True)` returns a duplicate of it
(`tc:4672`, `tc:4756`; the call at `tc:4901`). A `.tmp` that is this
user's own one-name regular file (a wait killed between create and
rename) is removed and the write tried once more; anything else there
is never opened or removed, and the write fails. A failed write is one
line to stderr; the exit code and the wake do not change. A wait
refused before it holds its lock writes nothing. The constants sit at
`tc:1087` to `tc:1130` (`WAIT_EXIT_NAME`, `WAIT_EXIT_MAX_BYTES` 64,
`WAIT_EXIT_TIME_STEP_SECONDS` 2). The module block lists the file
(`tc:17`).

**Item 2, the reader.** `read_wait_exit` (`tc:8726`) is the one reader.
It opens the record `O_NOFOLLOW | O_NONBLOCK` by name in the inbox's
descriptor and takes it only when `fstat` says a regular file with one
name, owned by the inbox's owner, at most `WAIT_EXIT_MAX_BYTES`, holding
one newline-ended line: a word of the three, a space, and a time with
its offset. Anything else is no record, and it never raises.
`wait_exits` (`tc:8781`) opens `mail/` once and each named inbox through
`pin_folder`, so health, watch and the board share one path.
`left_on_purpose` (`tc:8823`) is the one judgment: `mail` or `timeout`
dated after the last sighting of the lock, less the 2 s step, or any
date when the lock was never seen. `listeners()` (`tc:8540`) still reads
only locks.

**Item 3, `tc watch --names`.** The watch stamps `wall_clock()` before
each listing, keeps when it last saw each tracked lock held
(`tc:9381`), and alerts `LISTENER DOWN` only for a name whose lock went
and whose record does not say it left on purpose (`tc:9398`).

**Item 4, `tc health`.** `health_snapshot` reads the record of each
stopped name only (no pid) and stores `wait_exits` as
`{name: {"word", "age_s"}}` (`tc:9184`). `_who` (`tc:9196`) prints
`stopped: b (mail, 2m ago)`. `GATE_HEALTH_KEYS` (`tc:957`) is unchanged,
so the gate's allow list drops the key.

**Item 5, the board.** `feed()` reads every no-pid name's record
through `tc.wait_exits` (`board/serve.py:1295`) and asks
`stopped_state` (`board/serve.py:1304`, called at
`board/serve.py:1415`): record `listening` is `down`, seen or not, after
a restart and past `DOWN_WINDOW_S`; seen within the window, the D24 and
D28 rules run, and a `down` they give becomes no stopped state when the
record says `mail` or `timeout` dated after the sighting; no record
keeps the old rules. No new state, glyph or color. The module block
(`board/serve.py:91`) and `Board`'s block (`board/serve.py:1108`) say
what the record changes; `Board` holds nothing from it across polls.

## Not verified

- Nothing ran as a second Linux user. Another user's record is shown by
  patching `os.fstat` (`test_shared.owner_patched_fstat`), as the SHARED
  suites do.
- No person has walked `qa/human/health-watch.md` step 9 or
  `qa/human/board-live.md` step 23.
- Ctrl+C (SIGINT) leaving `listening` is claimed by both human scripts
  and by `cmd_wait`'s block; the tests kill with SIGKILL only.
- A wall clock that jumps (an NTP step) between a record's write and a
  sighting is not tested; the 2 s step covers the time cut to the second
  and the moment between the exit's write and the lock's release, not a
  jump.
- A stale bytecode cache can mask a mutation. `load_tc` in
  `tests/test_shared.py` loads `tc` with `SourceFileLoader`, which writes
  `__pycache__/tccpython-312.pyc` beside `tc`, and `load_serve` does the
  same for `board/serve.py`. Python checks a cache by the source's size
  and its mtime in whole seconds, so two same-size edits in one second
  run the old code. The first pass of this record hit it (R3 read as R2).
  The record above ran with no cache. This is about the tests' loaders
  only; `board/serve.py`'s own `load_tc` compiles in memory (C5).
